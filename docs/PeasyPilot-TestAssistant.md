## What is TestAssistant?

**TestAssistant** is an intelligent system that automatically generates test cases for your C# classes.

### What it does:

1. **Examines** your class using reflection
2. **Identifies** constructors and methods
3. **Proposes** test cases (nominal + boundary)
4. **Generates** test code (xUnit/NUnit/TUnit)

### Why is it useful?

- ⚡ Generates test cases in seconds
- 🎯 Automatically detects boundary cases
- 🔄 Supports 3 frameworks (xUnit, NUnit, TUnit)
- 📝 Generated code = starting point for you

## How It Works - Complete Pipeline

```
Your Class (Calculator.cs)
        ↓
    [ANALYZE]
    Examine via reflection
        ↓
  [GENERATE VALUES]
  Create test cases
        ↓
    [COMPOSE]
  Organize cases
        ↓
    [RENDER]
  Generate C# (xUnit/NUnit/TUnit)
        ↓
    TestFile.cs (generated code)
```

Let's look at each step in detail.

## Step 1: Analysis (Analysis)

### What happens?

TestAssistant uses **.NET reflection** to examine your class:

1. **Finds the constructor**
2. **Identifies constructor parameters**
3. **Scans public methods**
4. **Resolves parameter types**

### Concrete example

```csharp
// Your class
public class Calculator
{
    // Constructor
    public Calculator(ILogger logger)
    {
    }

    // Methods
    public int Add(int a, int b) => a + b;
    public int Divide(int a, int b) => a / b;
}
```

**What TestAssistant discovers:**

```
Class: Calculator

Constructor:
  - Parameter 1: "logger" of type "ILogger"
    → Resolution: Interface → needs mock

Public Methods:
  - Method 1: Add(int, int) → returns int
  - Method 2: Divide(int, int) → returns int
```

### Parameter Resolution

For each parameter, TestAssistant decides **how to generate it**:

| Type | Resolution | Example |
| --- |-----------|---------|
| `int` | Primitive value | Generates: 0, 1, -1, int.MaxValue |
| `string` | Primitive value | Generates: "", "a", "long text" |
| `ILogger` | Interface → Mock | `MockFactory.Create(typeof(ILogger))` |
| `MyRepository` | Concrete class | `new MyRepository()` |
| `DateTime` | Primitive value | Generates: min, epoch, now, max |

## Step 2: Proposal Generation

### What happens?

For each parameter type, TestAssistant generates **multiple values**:

### Values generated by type

**For `int`:**
```
Nominal:  0
Boundary: -1, 1, int.MinValue, int.MaxValue
```

**For `string`:**
```
Nominal:  "sample"
Boundary: "", "a", "very long text with 100 characters..."
```

**For `bool`:**
```
Nominal:  true
Boundary: false
```

**For `DateTime`:**
```
Nominal:  DateTime.UtcNow
Boundary: DateTime.MinValue, DateTime.MaxValue, new DateTime(1970, 1, 1)
```

**For `Enum`:**
```
Generates ALL enum values
If Color = { Red, Green, Blue } → generates 3 cases
```

**For `Decimal`:**
```
Nominal:  0m
Boundary: -0.01m, 0.01m, decimal.MinValue, decimal.MaxValue
```

### Combination Matrix

If your constructor has **2 parameters**:

```csharp
public Calculator(int precision, string format)
```

TestAssistant creates a **matrix** of test cases:

```
Case 1: precision=0,        format=""           → Boundary cases
Case 2: precision=1,        format="a"          → Boundary cases
Case 3: precision=int.Max,  format="very long"  → Boundary cases
```

### Structure of each generated case

```json
{
  "testName": "Calculator_CanInstantiate",
  "methodName": "Calculator",
  "description": "Nominal case: can instantiate the class",
  "category": "nominal",
  "parameterValues": {
    "logger": {
      "name": "logger",
      "type": "ILogger",
      "expression": "MockFactory.Create(...)"
    }
  }
}
```

## Step 3: Composition

### What happens?

TestAssistant **organizes** all generated cases into a structure:

```csharp
public class TestBatteryProposal
{
    public string TargetType { get; set; }           // "Calculator"
    public string TargetNamespace { get; set; }      // "MyApp.Math"
    public string Framework { get; set; }            // "xunit"
    public List<TestCaseProposal> TestCases { get; set; }  // All cases
    public DateTime GeneratedAt { get; set; }
}
```

### Complete example

```json
{
  "targetType": "Calculator",
  "targetNamespace": "MyApp.Math",
  "framework": "xunit",
  "generatedAt": "2026-09-09T10:30:00Z",
  "testCases": [
    {
      "testName": "Calculator_CanInstantiate",
      "description": "Nominal case",
      "category": "nominal",
      "parameterValues": { ... }
    },
    {
      "testName": "Add_HappyPath",
      "description": "Happy path for Add",
      "category": "nominal",
      "parameterValues": { ... }
    }
  ]
}
```

This structure is **ready for rendering**.

## How To Use It

### Basic usage

```csharp
using PeasyPilot.TestAssistant.Analysis;
using PeasyPilot.TestAssistant.Rendering;
using PeasyPilot.TestAssistant.Models;

// Step 1: Create an analyzer
var analyzer = new ReflectionTestScenarioAnalyzer();

// Step 2: Define options
var options = new TestBatteryAnalysisOptions
{
    TargetFramework = "xunit",    // or "nunit", "tunit"
    MaxEnumCases = 10,
    IncludeBoundaryTests = true
};

// Step 3: Analyze your class
var proposal = analyzer.Analyze(typeof(Calculator), options);

// Step 4: Render the code
var registry = new TestBatteryRendererRegistry();
var renderer = registry.GetRenderer("xunit");

var renderOptions = new RenderOptions
{
    OutputNamespace = "MyApp.Tests",
    Indent = "    "
};

string generatedCode = renderer.Render(proposal, renderOptions);

// Step 5: Write to file
File.WriteAllText("CalculatorTests.cs", generatedCode);
```

### Generate without file

```csharp
// Get generated code directly
string testCode = renderer.Render(proposal, renderOptions);

// Use or display
Console.WriteLine(testCode);
```

## Key Concepts

### Test Categories

Each generated case has a **category**:

| Category | Meaning | Example |
| --- |---------|---------|
| **nominal** | Happy path (main flow) | `Add(2, 3)` |
| **boundary** | Edge cases | `Add(0, int.MaxValue)` |
| **exception** | Error cases | Null parameter |

### Resolution Strategies

For each parameter, TestAssistant applies a **strategy**:

```csharp
public enum ParameterResolutionKind
{
    Primitive,                    // int, string, bool, DateTime, etc.
    ConcreteNewable,             // MyClass: can do new
    InterfaceOrAbstractNeedsMock, // ILogger: needs mock
    Unresolvable                 // Complex type, missing dependency
}
```

### Value Generation Rules

TestAssistant uses **rules** to generate values:

- `NumericValueRule` → `int`, `long`, `decimal`, `double`, `float`
- `StringValueRule` → `string`
- `BooleanValueRule` → `bool`
- `DateTimeValueRule` → `DateTime`
- `GuidValueRule` → `Guid`
- `EnumValueRule` → All `Enum` values
- `CollectionValueRule` → `IEnumerable<T>`, `List<T>`, etc.
- `NullableValueRule` → `Nullable<T>` types
- `FallbackValueRule` → Other types

## Summary: The Complete Cycle

```
1️⃣  ANALYZE
    └─ Use reflection to examine the class
    └─ Identify constructor, parameters, methods
    └─ Resolve types (primitive, interface, class)

2️⃣  GENERATE
    └─ For each parameter, generate multiple values
    └─ Nominal values (happy path)
    └─ Boundary values (edge cases)

3️⃣  COMPOSE
    └─ Organize all cases into a structure
    └─ Create a TestBatteryProposal

4️⃣  RENDER
    └─ Choose framework (xUnit/NUnit/TUnit)
    └─ Generate real C#
    └─ Write to file

5️⃣  REVIEW & IMPLEMENT
    └─ Read the generated code
    └─ Fill in the TODOs with real tests
    └─ Run and validate
```
